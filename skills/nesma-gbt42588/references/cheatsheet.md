# 决策规则速查 — GB/T 42588—2023 系统与软件工程 功能规模测量 NESMA 方法

| 能力 | 一句话规则 |
|---|---|
| 确定范围、边界、测量时点与分析方式 | 先固定用户、对象与边界，再按资料选预估/估算/详细；测量时点另按项目事件记录。 |
| 按模型层次计算预估功能点 | 概念模型用35×ILF＋15×ELF，规范化模型用25×维护实体＋10×引用实体，先合并FPA表且不混层级。 |
| 把规范化实体归组为逻辑文件 | 先排FPA表与纯键—键实体，再按可选性和业务依赖归组；双向强制1:1合并为1RET。 |
| 识别和归组FPA表及其标准事务 | 按内容识别FPA表，按维护方归成最多一个ILF组和一个ELF组；ILF标准事务各一，详细轴疑点单列。 |
| 判定跨应用共享、摘录和一次性传输 | 先分原始永久数据、传输载体和持久副本，再按边界、维护与消费方式匹配五种共享情形。 |
| 识别ILF/ELF与不计数的数据对象 | 永久逻辑数据按真实使用和维护责任判ILF/ELF，技术对象排除，维护缺口触发核查而不造功能。 |
| 识别基本过程并区分EI、EO、EQ | 按完整基本过程识别事务，以集合/布局/逻辑处理判独特性；EQ须同时满足唯一输入、明确规模、无派生处理及不维护ILF。 |
| 计数DET/RET/FTR、查复杂度并赋值 | 先确认功能类别并列元素证据，再按NESMA矩阵或有依据的专门/默认规则赋FP。 |
| 汇总估算与详细功能点并形成明细 | 按既定方式逐行赋值再加总；未决功能保留待计，不把已确定小计冒充完整总量。 |
| 识别变更并计算开发、增强、重建规模 | 增强项目计新增+删除+修改后；应用存量还要扣删除与修改前，必要转换只进项目。 |
| 从套装、界面和原型材料恢复可计数需求 | 从材料恢复带证据的候选，区分所需、缺失和额外功能；屏幕与菜单不直接等于功能。 |
| 处理帮助、菜单、消息、列表、工具等特殊功能 | 按责任、数据来源与完整过程分流特殊对象；帮助按类型去重，消息、工具和列表保留专门条件。 |
| 审查重复、遗漏、默认值与证据链 | 先对齐边界和证据再复核重复遗漏；缺维护或EO只触发调查，不机械补造功能。 |
| 区分需求细化与范围变更并记录增长依据 | 用前后需求证据区分原需求细化与新范围；附录增长率仅是示例，不作为通用预测。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
