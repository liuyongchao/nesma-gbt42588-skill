# 计数 DET/RET/FTR、查复杂度并赋值

## R — 原文

> “对所有跨越应用程序边界（进入或离开边界）的功能性数据进行计数。”
> “输出本身出现的控制信息应计数两次。”

出处：GB/T 42588—2023，6.23、10.3.1.2，印刷34、44页／PDF38、48页。完整计算依据为7.3–11.3、规范性附录B和表1。

## I — 自述

先确认功能存在、类别和边界，再计算其元素数量。
DET是业务信息的类型，不是记录条数、字段取值、像素或控件数量。
数据功能只统计本应用相关属性；合并实体时剔除内部引用属性的重复计数。
RET来自已经完成的实体归组，不能直接照抄物理表数。
事务必须考察整个基本过程的输入、输出、验证和维护。
FTR统计合格的逻辑文件，普通事务不把FPA表或临时载体算作引用文件。
EO/EQ中输入控制又出现在输出时，本标准要求两次计DET。
等级由本标准矩阵决定；实现困难或开发工时不决定等级。
原文允许复杂度资料未知时采用默认等级，但功能存在与类别未知不能靠默认值补齐。
帮助查询和FPA标准事务应先进入专门分支，避免通用矩阵覆盖特殊规则。

## A1 — 来源例与演练

原文说明性示例：10.3.1.2–4（印刷44／PDF48）列出选择条件、介质、打印机、排序、打印时间段等控制信息，以及平均值、小计、总计等派生输出；控制信息同时输入和输出需计两次。原文未给这个示例的完整字段表和FP结果。

合成演练：区域汇总EO输入区域代码，输出该代码和计算总金额；外部启动一次，无消息或其他跨界数据，只读一个普通ILF。区域代码计2DET，金额1DET，启动1DET，共4DET；FTR=1，EO低=4FP。固定标题、页码、系统日期、翻页键不计。此例是规则演练，不是标准中的现实项目或独立测试证据。

## A2 — 何时使用

- 有需求字段及文件清单，询问“DET、RET、FTR各是多少／count data elements and referenced files”。
- 已知元素数量，要求“查NESMA复杂度矩阵／complexity matrix and weights”。
- 复杂度材料缺项或靠近阈值，询问“能否默认低/中、帮助如何计／missing counts, defaults, help query”。

与相邻能力的区分：功能类别和基本过程未定，先用 `nesma-data-functions` 或 `nesma-transaction-functions`；实体归组未定，先用 `nesma-logical-data-groups`。本能力负责单功能赋值；完整应用合计交给 `nesma-fp-aggregation`，特殊对象识别交给 `nesma-special-functions`。

## E — 执行

**输入契约。** 每条需要唯一功能ID、应用边界、已确认类型ILF/ELF/EI/EO/EQ、方式estimated或detailed、原始字段/控制/文件证据、普通/帮助/FPA标准事务标识。DET、RET、FTR为整数个数；FP为整数。未知用null，不用0伪装未知。详细数据功能DET≥1、RET≥1；详细事务DET≥1、FTR≥0。表中未定义的零DET/零RET不能擅自落到第一档。

1. **检查前提与专门规则。** 功能类型或边界未定，输出待补充输入并停在赋值前。帮助EQ：详细低=3FP、估算中=4FP（6.13）。FPA标准事务详细计数涉及NR04：保留数量和已知条件，输出原文歧义待复核；不得把其“引用记录类型”无提示当作普通FTR或设为0。估算已识别事务可按估算中级赋值，并明确这未解决详细口径。涉及系统消息转NR03；不得用默认复杂度掩盖已知冲突。
2. **建立元素明细，逐项给纳入/排除理由。**
   - 数据DET：ILF统计本应用使用或维护的属性，ELF统计本应用使用或将使用的属性；FPA数据组同样只纳相关属性。合并实体时去除同一LF内部引用属性的重复项，不能仅凭字段同名机械去重（7.3.1、8.3.1）。
   - RET：通常为LF包含的实体类型数；FPA组为所含FPA表数。双向强制1:1归组例外为1RET，依6.21.5判断，不从“实体有两个”直接推2RET（7.3.2、8.3.2、附录B）。
   - 事务DET通则：计所有跨界功能性数据、实际显示的LF/FPA字段、输入选择条件、输出派生值、设备/介质地址等。每个基本过程外部启动合计1DET，无论按钮、菜单、步骤多少；纯内部控制不能虚构跨界触发。附属功能反馈在该事务共计1DET，不按消息条数计。
   - EI：把整个过程相关屏幕合并统计；同屏增删改按各自实际数据分别统计；响应显示的附加数据纳入该EI；用户要求的事务文件头尾校验数据也计DET（9.3.1）。
   - EO/EQ：输入控制与输出数据均纳入；同一控制输入后又输出计两次。EO计平均值、小计、总计等计算结果；只在LF内部读取、没有跨界的字段不计事务DET。用户要求的头尾校验数据计DET（10.3.1、11.3.1）。
   - 排除：标题、表头、标签、固定文字/常量、页码、系统日期、滚动翻页和导航；仅内部更新的字段不计事务DET。图形按跨界信息计，不按画图技术计。
3. **建立引用文件明细。** 普通EI/EQ计验证及执行所用的不同ILF/ELF；普通EO计验证输入及生成输出所用文件，与EI绑定的事务报告要看整个相关处理，不能只数最后打印步骤。相同LF在同一事务去重。排除FPA表ILF/ELF、事务输入/输出文件、临时/排序/打印/恢复校验等技术文件；技术替代文件追溯底层合格LF，不漏计也不重复（9.3.2、10.3.2、11.3.2）。
4. **选择等级。** estimated直接采用数据低、事务中。detailed普通功能在参数已知时查以下矩阵；已识别类型但必要参数未知，可依附录B采用数据低、事务中，并记录缺项、默认依据和明确的采用决定，不冒称参数已核实。特殊帮助优先于一般默认。

| ILF/ELF：RET \ DET | 1–19 | 20–50 | ≥51 |
|---|---|---|---|
| 1 | 低 | 低 | 中 |
| 2–5 | 低 | 中 | 高 |
| ≥6 | 中 | 高 | 高 |

| EI：FTR \ DET | 1–4 | 5–15 | ≥16 |
|---|---|---|---|
| 0–1 | 低 | 低 | 中 |
| 2 | 低 | 中 | 高 |
| ≥3 | 中 | 高 | 高 |

|---|---|---|---|

5. **复算并交付。** 可用 `resources/nesma_calc.py`，命令 `python nesma_calc.py input.json --output result.json`；单功能请求为 `operation: complexity`，含method、type、det和ret或ftr、special。详细缺值只有显式 `allow_defaults: true` 才允许默认；接口见 `resources/calculator-guide.md`。脚本只校验算术与字段，不能确认字段语义或功能类别。所有运算保持整数，无舍入；逐行值与矩阵/权重应完全相同。

**输出契约。** 输出功能ID/类别/边界/输入证据、DET明细及排除项、RET归组或FTR清单、数量、矩阵行列或专门/默认依据、复杂度、权重FP、状态及待核查编号。状态采用本技能约定：可确定、按标准默认值估算、待补充输入、原文歧义待复核。不同状态分列；有歧义不输出无条件确定分值。明细、算式和资源计算结果一致才完成。

## B — 边界

- 不从控件数、物理表数、代码复杂度或工时推FP；未知类别不能默认成中复杂度事务。
- NR02：附录D给定11DET/2FTR可复算，但不能证明每个真实事务都有相同元素；不得补造其遗漏字段。
- NR03/NR04见 `resources/source-issues.md`：系统消息与FPA标准事务详细轴留待复核；已知争议不属于普通参数未知。
- 这里的EQ阈值与EO一致，以本版本附录B为准，不替换成其他FPA体系记忆中的矩阵。
- 普通事务不把FPA表计FTR，不等于从DET里排除用户实际看到的FPA字段。

相关能力：依赖 `nesma-logical-data-groups` 的归组和 `nesma-transaction-functions` 的分类；与 `nesma-special-functions`、`nesma-fp-aggregation` 组合使用。
