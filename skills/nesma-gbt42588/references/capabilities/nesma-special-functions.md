# 处理帮助、菜单、消息、列表、工具等特殊功能

## R — 原文

> “如果应用程序提供帮助功能，则应用程序中的每一种类型的帮助功能计数为一个外部查询。”
> “在功能的级别进行计数，不要将每个内部逻辑文件计为一个外部输入。”

出处：GB/T 42588—2023，6.13、6.18，印刷25–26页／PDF29–30页；其他分支见6.1–6.18、第9–11章。

## I — 自述

特殊对象需要先问它为用户提供什么功能，再看属于哪个专门分支。
复用技术、显示设备、图形难度和入口数量不直接增加或减少功能点。
帮助按类型在应用内归并，不按屏幕数量重复计查询。
菜单通常是导航，但可维护菜单自身可能产生真正的数据和输入功能。
功能反馈通常属于原事务；独立报告必须另按完整功能识别。
列表的数据来源决定走普通输出、FPA归组还是字段帮助。
通用工具与本应用必须构建的用户功能要区分责任，不能一律排除安全或工具。
清除归档按完整过程计，不按被清理的文件数量拆事务。
原文冲突仍是冲突，不能用“特殊情况”作出无依据的自动结论。

## A1 — 原文说明性示例

6.13，印刷25／PDF29：同一类屏幕帮助可以在每个窗口调用，但在整个应用内按一个EQ计。原文同时列全应用帮助、屏幕/窗口帮助、字段帮助、交互向导、上下文索引等类型；可维护帮助文本按FPA表处理。详细帮助EQ为低=3FP，估算为中=4FP；没有提供某现实项目实际使用成效。

## A2 — 何时使用

- “登录、帮助、菜单、下拉列表要不要计／login, help, menu, selection list counting”。
- “报表工具、复用代码、清除归档怎么算／report generator, reuse, purge and archive”。
- “消息算DET还是EO、同报表多设备算几个／message versus report, multiple media”。

与相邻能力的区分：本能力处理专门分支和是否纳入的证据，普通EI/EO/EQ独立性及分类用 `nesma-transaction-functions`；FPA组的实际归组用 `nesma-fpa-table-groups`；普通元素与赋值用 `nesma-elements-and-complexity`。

## E — 执行

**输入契约。** 需要应用边界、用户需求、功能责任/提供方、对象用途、数据来源、是否可维护、是否独立调用及处理逻辑、分析方式。对象名称不足时先索取影响分支的事实。记录需求定位及排除依据；工具能实现功能不等于工具本身就是一个计数功能。

1. **检查通用视角（6.1–6.8）。** 用业务逻辑而非实现难度计；在同一应用内相同功能只计一次。分开用户所需与实际额外提供的功能范围。复用既有代码或为复用开发不改变已实现用户功能的FP；生产率另有依据时另论。屏幕、窗口、报告、输入输出记录与逻辑功能多对多，不按物理数量机械计数。
2. **按下表执行专门分支。** 每行完成标准是给出纳入/排除/待补充结论与事实依据；纳入后仍需辨别实际五类功能，而不是“一对象固定一功能”。

| 对象与条件 | 执行规则 | 来源 |
|---|---|---|
| 通用安全、授权、登录 | 通用标准供给通常排除；若必须在当前被测应用内构建，则纳入功能识别，不能固定加一个EI | 6.9 |
| 标准OS、环境工具及其技术裁剪 | 通常不计；仅为适应技术环境修改/裁剪OS不增加用户功能 | 6.10 |
| 报表生成器/查询工具 | 开发环境标准工具本身不计；用户要求的特制工具按交互流识别五类功能，包括输出定义、保存查询等。借工具构建的固定业务报表/查询仍按EO/EQ计；工具本身不是简单一个EQ | 6.11、11.2.4 |
| 图形 | 识别输出功能后按跨界信息DET定复杂度；不按像素、图形制作技术或绘制困难定等级 | 6.12 |
| 帮助 | 按全应用/屏幕窗口/字段固定值/交互向导/上下文索引等真实类型在应用层面去重，每类一个EQ；不是每个屏幕一个。详细低3FP、估算中4FP。可维护帮助文本另转FPA表识别 | 6.13 |
| 附属功能反馈 | 同一事务中的业务校验/成功等功能消息共1额外DET；不按条数加EO，不重复计固定标签。消息包含独立业务信息时须核实整个过程，不能一律压成反馈 | 6.14、6.23、10.2.13–15 |
| 日志/错误报告 | 供多个事务或重复运行调用的报告按第10章检查独立输出功能；有EO证据才纳入。可能出错消息目录不单计EO；可维护消息实体转FPA表 | 6.14、10.2.13–16 |
| 系统消息 | 6.14与6.23(d)措辞不同，标NR03；保留两处来源及受影响DET，不能无条件说全部计或全部不计 | NR03 |
| 固定菜单/按钮导航 | 不另计功能；外部触发每个已识别事务启动共1DET，不随菜单级数、按钮/功能键数量增加 | 6.15、6.23(c) |
| 可维护菜单结构/文本 | 进入LF与EI识别；核查是否FPA表，不凭一句可维护就断言固定1ILF+1EI | 6.15、6.20 |
| 普通LF中的可选择列表 | 用户要求、非唯一候选、数量事前未明时按EO识别；选项不逐个计功能 | 6.16–6.17、10.2.20 |
| FPA表中的列表 | 依FPA整体规则处理，不额外计该显示列表功能；不因排除列表便解决FPA标准事务详细复杂度 | 6.16、NR04 |
| 不在普通LF或FPA表中的固定选项 | 转字段级帮助，按帮助类型在应用内去重 | 6.16、6.13 |
| 浏览、滚动、翻页 | 作为输出支持方式不加功能或DET；真正独立的新业务处理仍须按完整过程检查 | 6.17、10.2.21、11.2.10 |
| 删除、清除、归档 | 用户要求的在线或定期完整清除功能按EI识别；一次涉及多个ILF不拆成多个EI | 6.18 |

3. **检查物理展示与过程组合。** 相同逻辑布局、相同处理而输出到屏幕/弹窗/打印机等只算一个输出；单个物理输出若含可独立检索的不同逻辑布局/不同处理，需分别识别。事务文件的头尾处理本身不另计EI/EO，用户要求的校验数据可计DET。编辑前自动回显、修改确认属于原EI；明确独立查询或独立授权基本过程按其真实条件另识别（9.2、10.2）。
4. **转入赋值并保留疑点。** 对纳入的功能传递类别、帮助/FPA特殊标识、去重ID和证据给 `nesma-elements-and-complexity`。NR03系统消息以及NR04的FPA标准事务详细轴输出待复核，不采用普通缺参默认来绕过。复杂度数据未知而无来源冲突时，才用标准允许的默认。

**输出契约。** 交付“对象—需求/责任证据—专门分支—纳入/排除/待补充—功能候选ID及类别—去重标识—元素影响—来源—未决项”的表。帮助另列类型清单及3/4FP选择依据。可用 `resources/measurement-template.json` 组织计数；冲突细节见 `resources/source-issues.md`。先完成可确定部分；待复核部分不伪装零分或确定值。

## B — 边界

- “通常不计”带适用条件，不能推成所有登录、授权、工具一律排除；纳入也不代表已经确定数量与复杂度。
- 功能性反馈共同口径可用，但系统消息有NR03；FPA显示列表不独立计数不等于所有相关FPA事务零分。
- 附录D将多匹配查询列EQ的叙述存在NR01；一般列表依正文条件判断，不能借案例标签覆盖条件。
- 报表、查询和输入的组合要保持完整基本过程，不按按钮、页面和介质分割。

相关能力：与 `nesma-transaction-functions`、`nesma-fpa-table-groups`、`nesma-elements-and-complexity` 组合使用。
