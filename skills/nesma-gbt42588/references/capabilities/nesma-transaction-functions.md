# 识别基本过程并区分EI、EO、EQ

## R — 原文与定位

> 外部查询输入部分的数据必须能够唯一地标识所需的输出。此外，输出的规模必须完全明确。

GB/T 42588—2023，11.1，印刷第45页 / PDF第49页。完整依据：9.1–9.2、10.1–10.2、11.1–11.2，印刷第38–46页 / PDF第42–50页；列表与浏览另见6.16–6.17，印刷第26页 / PDF第30页。

## I — 方法自述

先找到用户认为完整、自包含且结束后应用状态一致的基本过程，再给它分类。
屏幕、按钮、步骤、接口和物理输出都是实现载体，不直接等于事务数量。
EI把跨界数据或控制带入应用，通常维护ILF，也可控制进程。
EO是跨界输出，规模不固定或包含进一步数据处理；控制它的输入属于该输出过程。
EQ是唯一标识输入与规模明确、无进一步处理输出的完整组合，且不能维护ILF。
同类事务的独特性按数据元素集合、逻辑布局和用户要求的逻辑处理差异判断。
重复入口、语言、介质和执行次数不会自动产生新的事务；独立业务过程也不会因共用一张屏幕就合并。
列表、修改前显示、组合输出等情形须保留专门分支，不能把所有名叫查询的功能都算EQ。

## A1 — 原文情境

类型：原文规范性示例，9.1，印刷第39页 / PDF第43页，案例c35。

录入新员工时，用户要求同时输入员工基本信息、薪资和家庭状况；仅输入姓名或仅输入薪资均不构成完成状态。先把这些输入组合为一个完整过程，再作为一个EI，而非按薪资页和家庭页分别计数。它维护几个ILF并不改变这个整体性的判断。若实际项目允许各部分单独作为完整业务过程维护，则应按其不同事实重新识别。原文没有DET/FTR和FP结果，不补造数值。

## A2 — 触发与邻近区分

- 划分事务颗粒度：“三个页面算几个功能”“what is an elementary process”。
- 判类别：“客户查询属于EO还是EQ”“EI vs EO vs EQ classification”。
- 复核重复/组合：“打印和导出算两次吗”“unique transaction, logical layout, combined output”。

本卡识别基本过程、类别与独特性；复杂度和DET/FTR数量交 `nesma-elements-and-complexity`。帮助、菜单、消息与工具等专门规则组合 `nesma-special-functions`；接口传输文件与ELF之间的判断组合 `nesma-shared-data`。不从总FP反推事务明细。

## E — 执行

**输入契约。** 每候选过程需有ID、用户目标、触发者和触发条件、输入/输出字段类别、跨界方向、维护/引用的逻辑数据、算法/计算/验证、完成条件；EQ还需唯一标识参数及明确的输出规模；EO还需逻辑布局、分组、排序/选择方式、独立与组合运行。字段数量可以尚未知，但足以判断集合是否不同的证据不可省。边界不明先停止分类并回范围能力。

1. **划定完整过程。** 检查用户已定义、可单独识别的业务目的、跨界、自包含、完成后一致状态。只因技术引入且用户不要求的过程排除；系统内部组件间传递不冒充越过应用边界。完成标准：一个候选过程有清楚起点、完成状态和用户结果。
2. **检查类别条件。**

   | 类型 | 核心条件 | 要避免的拆分 |
   |---|---|---|
   | EI | 用户认可的独特完整过程；外部数据和/或控制进入；通常新增/修改/删除ILF，也可激活/停用进程或影响处理 | 多屏、确认提示、技术时间延迟、维护多个ILF不自动拆 |
   | EO | 用户认可的独特完整跨界输出；输出规模大小不等或需要进一步数据处理 | 为此输出输入的选择、排序、打印控制不是另一个EI |
   | EQ | 用户单独发起的完整输入/输出组合；四项条件必须同时成立：①输出规模明确；②输入含唯一标识查询参数；③输出不含进一步处理产生的数据；④不维护ILF | 输入不是另计EI、输出不是另计EO；修改/删除的附带显示不是独立EQ |

   EQ可进行引用文件与授权等验证，不能把允许的验证一概当作EO的计算派生结果。EO不要求必须有用于选择数据的输入；固定字段布局也不表示输出记录规模固定。若EQ任一条件不成立，结合实际用户过程再检验EO或EI，而非机械把所有未知归EO。完成标准：分类表逐项记录条件是/否/未知及依据。
3. **用独特性证据去重。**
   - EI：输入DET集合不同，或集合相同但逻辑处理不同。不同逻辑处理包括维护/引用不同LF，或同LF上算法、计算、验证不同。
   - EO：输出逻辑布局不同，或布局相同但处理不同，或输入部分DET集合不同。相同字段换输出顺序仍可同布局；改变分组结构如中间标题分组是不同逻辑布局。某字段为空或对部分用户不可见不自动形成新布局。不同LF、算法/计算/验证可形成不同处理；同字段换选择值、通配符或运算符不自动算不同处理，技术方案变化也不算。
   - EQ：输入DET集合不同，或输出DET集合不同，或两边集合相同而引用文件/验证逻辑不同。
   完成标准：每一新增同类事务都有明确差异；同一应用相同事务只保留一次。
4. **保留EI的必要分支。** 用户把维护多个ILF视为不可分整体→一个EI；数据可独立维护→分别识别相应独特基本过程。新增、修改、删除确为不同功能时分别计。普通确认提示属于原过程；初始输入与另一人员授权如果各为基本过程，则分别计EI。多屏必须顺序组合才能完成→一个EI；各屏可独立使用且本身完整→分别识别。单独定义并发起的查询可另计EQ，即使随后能修改；编辑前自动显示属于EI。跨介质的相同输入处理去重；事务文件内不同记录/处理代码只有导致不同逻辑处理才可能多个EI。头尾校验记录不独立计EI，但用户要求的校验数据交DET计数。非唯一选择后生成普通LF列表以供修改/删除时，另按EO分支核查。完成标准：多屏、确认、授权、文件记录数等均未被直接当作事务数量。
5. **保留EO的必要分支。** 同布局同处理的屏幕/打印/文件、多语言输出及多物理产品计一个EO；仅排序变化仍一个，除非有额外或不同逻辑处理。一个物理产品含可独立检索的不同逻辑布局，或不同处理生成后为了方便而合并的布局，可含多个EO；混合事务输出文件同理。先列真正互斥的选择或选择组合，10.2.17要求分别计数；记录各支用户定义的差异，并结合10.1上述独特性规则复核，不把同字段不同选择值/运算符按所有排列相乘。可独立运行且处理不同的功能各计EO；组合效果超出部分之和时通常增加一个组合EO，只有不同逻辑处理的组合组才再分别增加。用户维护过程的逻辑结果报告、跨事务/重复运行日志按实际独特输出识别；单事务反馈消息不是逐条EO。头尾校验记录不独立计EO；仅技术后台打印文件不计。完成标准：逻辑输出及组合附加项有独立效果/布局/处理证据。
6. **处理列表、浏览与永久数据。** 普通逻辑文件产生、规模事先未知的用户选择列表按EO；选择机会与浏览/翻页本身不另增功能。FPA表列表及固定值帮助走特殊功能规则，不能直接套普通LF列表。直接供另一应用使用的永久数据，先识别提供方ILF/使用方ELF，不把文件本身再当EO/EI；创建一次性传输或功能摘录过程按共享数据五情形判断。完成标准：文件数据功能、传输事务及辅助交互不混计。
7. **交接计算与缺口。** 形成去重后的EI/EO/EQ清单，连同输入/输出字段、相关LF和特殊标签交元素计数。只知功能名称、唯一性/规模/处理不明则保持候选并问必要事实，不出确定类别及完整FP。完成标准：每项要么条件闭合，要么明确缺口和受影响结论。

**输出契约。** `process_id / user_goal / trigger / boundary / completion_state / input_DET_set / output_DET_set / maintained_LFs / referenced_LFs / calculation_validation / output_extent / unique_identifier / logical_layout / classification_conditions / EI_EO_EQ / uniqueness_basis / merged_with / split_reason / special_case / evidence / unresolved_issue / status`。字段集合可用名称清单表达，不要求此时给出最终DET数。使用资源 `measurement-template.json` 记录，原文类比素材见 `source-cases.json`。

## B — 边界与判停

- NR01：附录D把多匹配客户查询列为EQ，与正文唯一参数、明确输出规模及列表条款有张力。保留其原标签事实，不用作“所有列表都是EQ”的先例；一般分类按本卡完整条件，案例本身待核查。
- 功能名称、按钮数、屏幕数、记录数、运行次数或介质数均不足以单独决定数量。未知条件不能以“常见做法”补足。
- 仅缺DET/FTR数量不必推翻已经充分证明的类别，但最终复杂度只能按专门默认或已核参数处理；分类缺依据不能靠默认复杂度补救。
- NR03系统消息与NR04 FPA标准事务复杂度属于后续计数边界；本卡不将所有消息变成EO、不替FPA标准事务选择详细轴。NR05检查缺EO只能促核查，不能造EO。NR06先锁边界。NR02附录明细不能替代本项目的真实字段和引用。参见 `source-issues.md`。
- “查询工具”是可能由多个EI/EO/EQ构成的应用结构，不能把整个工具当一个EQ；必要时回范围能力。
