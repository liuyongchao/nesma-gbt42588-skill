# 审查重复、遗漏、默认值与证据链

## R — 原文

> “如果缺失了这些功能，请询问用户是否有所遗忘，以及文件是否真的和应用程序相关。”

出处：GB/T 42588—2023，6.19，印刷26页／PDF30页；复核流程见5.1步骤6–7、6.2–6.3，印刷9、23／PDF13、27。

## I — 自述

复核是检验证据、范围和规则的一致性，不是把检查清单每个格子填满。
先对齐目的、边界、版本和分析方式，才比较数量。
相同功能在同一应用只计一次，但独立边界下的角色可能不同。
数据与事务相互印证，可以发现遗漏，也可能暴露不该计的数据对象。
找不到维护或输出时应调查原因，不能自动补一个EI或EO。
明确默认依据与来源疑点，使结果既可复算也可追问。
审核通过的部分与仍待输入、待解释的部分必须分开。
用户确认测量约定是记录的一部分，不能使原文冲突自动消失。

## A1 — 原文说明性示例

6.3，印刷23／PDF27：“更改客户”在应用中多处出现，只要功能相同就计一次。同一LF在该应用只能是ILF或ELF之一。执行时把入口映射到相同需求/基本过程及相同逻辑数据标识，再合并重复；原文未给具体重复金额或现实项目结果。

## A2 — 何时使用

- “复核这份功能点清单，找重复遗漏／audit function point count”。
- “供应商计数与我们不一致，说明差异／reconcile counts and evidence”。
- “一个ILF没EO要补吗、默认能否接受／missing maintenance or outputs, default complexity review”。

与相邻能力的区分：本能力出审查意见和修订依据，不直接代替 `nesma-data-functions` 或 `nesma-transaction-functions` 重新发明功能；重算交给 `nesma-fp-aggregation`，范围争议交给 `nesma-scope-and-method`。

## E — 执行

**输入契约。** 需要被审计清单及版本、目的/应用边界、原始需求材料、分类/元素/复杂度证据、默认/假设清单、原算式；比较计数需两方相同字段及范围说明。只给总数时可以查算式或指出不可追溯，不能反造唯一明细。

1. **核对范围与口径。** 检查应用vs项目、边界、时点、预估/估算/详细、需求功能vs全部提供功能是否相同。不同口径先报告差异，不把总数不同直接判为错误。NR06：独立子项目与整应用计数不能混用；边界未定的共享项暂停确定汇总。
2. **检查重复。** 同一需求/基本过程跨菜单、用户、媒介、语言等是否重复；相同逻辑布局与处理的多输出是否重复；一个LF在同一应用是否同时ILF和ELF，多个视图、索引、物理副本是否误加LF。保留被合并ID及证据，不只删行改总数。
3. **反查数据与事务完整性。** 为每个ILF列实际维护EI与读取/输出；为ELF列使用与外部维护方。候选ILF无维护时按7.2.3检查：是否外部维护而属ELF/一次输入；需求是否遗漏维护；是否仅技术文件不应计LF。只验证/编辑用的ELF可没有独立EO/EQ。对缺项索取事实，不自动生成维护或报告。
4. **检查分类、元素与默认。** 每行是否满足类型条件；EQ是否独立发起、唯一识别、输出规模明确、无进一步处理且不维护ILF；DET/RET/FTR清单能否支持等级；FPA、帮助、消息是否走专门分支；是否把FP算术与语义正确性混为一谈。默认需有已识别功能、明确缺项和标准条款，不能用默认盖住原文争议。
5. **检查全部来源边界。**
   - NR01：附录D的多匹配查询标签不能当通用EQ金标准。
   - NR02：D给定50/37/37的复算与明细重建、增强范围确认分开；不补造备注、字段或基线。
   - NR03：系统消息DET措辞冲突，要求明确适用说明或记录项目约定。
   - NR04：FPA标准事务详细“引用记录类型”轴不直接当普通FTR；未决部分保留待计。
   - NR05：6.19/10.2.6要求ILF有EO，而7.2.4允许EO或EQ。若仅有EQ，列事实与条文差异待复核；既不机械加EO，也不无条件宣称完整性已通过。
   - NR06：必须区分独立项目边界与单一整体应用边界，不双计整体共享LF。
   逐项来源及影响见 `resources/source-issues.md`。
6. **复算并形成修订闭环。** 对证据充分的错误给出原值、建议值、原因与条款；未决项给出所缺事实/解释和受影响范围，不臆造数值影响。重算已确定部分，保持待计项。依5.1将特殊解释与用户共同确认，必要时请FPA专家复核；本技能不能代替这一确认。

**输出契约。** 交付审查表：issue_id、功能ID、发现、输入证据、条款、结论状态、原值、建议处理/条件化影响、补充资料、处理记录。另给确定修订后的明细/小计、剩余重要缺口、结论适用范围。表字段与“可确定/默认/待输入/待复核”状态是本技能实施约定。重要缺口未闭合不能写“完整国标验收通过”；可说明已完成本次审阅且列出未决项。

## B — 边界

- 缺EI或EO是调查信号，不是新增FP的授权；发现技术文件不应为满足清单再造业务功能。
- 只看总量或脚本通过不足以证明需求完整。未取得材料不能声称已核实某个事实。
- 不把组织项目约定、个人经验或本技能输出格式冒充国标明文；保留其来源与适用范围。

相关能力：依赖 `nesma-scope-and-method`；与 `nesma-data-functions`、`nesma-fp-aggregation` 组合形成可复算修订。
